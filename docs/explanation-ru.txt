РОЛЬ 2 — Nurym Zhumabayev

Что говорить на защите
Я сделал главную страницу, общую шапку и навигацию. Сервер получает фильмы из MySQL через существующий Drizzle-клиент и передает данные в Handlebars. Шаблон превращается в обычный HTML. CSS задает внешний вид и две колонки на телефоне. JavaScript нужен только для подтверждения удаления и замены неработающей картинки.

Файлы
views/home.hbs — разметка главной. {{#each movies}} повторяет карточку для каждого фильма. {{#if}} показывает блок только при выполнении условия.
views/layouts/main.hbs — общая оболочка HTML: head, header, main, footer.
views/partials/header.hbs — шапка, поиск, ссылки входа или аккаунта.
views/render.ts — читает шаблоны и вставляет в них данные.
public/css/home.css — простые стили, Grid для карточек и media query для телефона. Студент 5 сможет перенести их в общий style.css.
public/js/home.js — confirm перед отправкой формы удаления и замена отсутствующего постера.
movies/catalogue.ts — запросы к реальным таблицам movies и reviews.
movies/home.ts — GET /, поиск и POST /movies/:id/delete.
app.ts — подключение маршрутов и раздача public-файлов.
docs/role-2.html — sitemap, user journeys / task flows, storyboard. Открывается прямо в браузере.

Как работает главная
1. Браузер запрашивает GET /.
2. Сервер читает фильмы и присоединяет отзывы через LEFT JOIN. Поэтому фильм без отзывов не пропадает.
3. COUNT считает отзывы, MAX выбирает самую свежую дату отзыва.
4. Если MAX вернул null, показываем дату добавления фильма.
5. DATE_FORMAT задает YYYY-MM-DD. В проекте даты хранятся в UTC.
6. Поиск сравнивает название и строку q без учета регистра.
7. Handlebars выводит карточки. Обычные {{title}} экранируют HTML, поэтому название не выполняется как код.

Администратор
В готовом бэкенде не было поля роли. Поэтому используется настройка ADMIN_USER_IDS в .env: перечисление ID существующих пользователей через запятую. По умолчанию список пуст, удалять не может никто. Это серверная настройка, пользователь не может назначить себе права через форму. Не ставьте произвольный ID: проверьте ID нужного аккаунта в таблице users.

Удаление
Кнопка видна только администратору. JavaScript спрашивает подтверждение. Затем сервер снова проверяет сессию, ID администратора, CSRF-токен и ID фильма. После удаления внешний ключ ON DELETE CASCADE удаляет отзывы фильма. Сервер отвечает 303 и возвращает пользователя на главную. Если JavaScript выключен, форма отправляется без окна confirm; проверка прав и CSRF остается на сервере.

Что уже есть у команды
Регистрация /register, вход /login, аккаунт /account, выход POST /logout, таблицы и сессии — работа из dev. Страниц /movie/:id и /movies/add в исходной ветке еще нет. Как запустить
Установить Deno и MySQL. Скопировать .env.example в .env и заполнить параметры своей БД. Выполнить deno install, deno task db:migrate, deno task db:seed-users, deno task start. Открыть http://localhost:8000/.
Если фильмов нет, это нормальное пустое состояние: сиды фильмов относятся к студенту 3.

Проверки
Тест tests/home_test.ts использует тестовое хранилище, не реальную MySQL. Он проверяет даты, поиск, пустой список, экранирование и запрет удаления гостям/обычным пользователям, проверку CSRF и успешное удаление администратором. Проверка SQL с вашей MySQL требует настроенной БД.
