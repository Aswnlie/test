2. User journeys and task flows

A. Visitor finds a film

Goal: find an interesting movie without creating an account.

Open home → scan featured film and posters → search by title → choose Details → read movie information

Decision: if no result matches, try a shorter title or use Clear search. If the catalogue is empty, show “No movies yet”.

Experience: curious → compares titles and years → confident that the selected film is the right one. Success means reaching the intended film's details.

B. Member adds a movie

Goal: share a film with other users.

Home → Log in to add a movie → login → account → Home → Add movie → complete form → save → return to catalogue

Decision: new visitor registers first, then logs in. Invalid credentials keep the visitor on the login form with an error. The planned add form should retain input when validation fails.

Experience: motivated → completes sign-in → sees their contribution in the catalogue. Success means a stored movie shown with its title, year, poster and added date.

C. Member reads and writes a review

Goal: compare opinions and share their own.

Home → Details → log in if necessary → Home → reopen film → read reviews → choose rating and write review → submit

Decision: unsigned visitors see the movie information; review visibility and form access are handled by Student 5. After a successful review, the home card uses the latest review date.

Experience: interested → informed → involved. Success means a stored review and an updated last-review date on the homepage.

D. Administrator removes a movie

Goal: remove an unsuitable catalogue entry.

Log in → Home → find movie → Delete → confirm → server checks session, admin ID and CSRF → delete → Home

Decision: Cancel leaves the movie unchanged. Without permission, the server rejects the request; with an expired form, reload and retry. A missing movie returns 404.

Experience: cautious → verifies title in confirmation → receives success feedback. Success means the movie and its related reviews no longer exist.

4. Design decisions and implementation

  • The structure follows the supplied wireframe: header and search, featured movie, recent movies, catalogue and footer.
  • Desktop uses six catalogue columns; tablet uses four; small screens use two. Recent movies are hidden on mobile as in the wireframe.
  • Popular means the highest number of reviews. With equal counts, the newest movie wins. Recent movies are the newest entries excluding the featured film.
  • Search uses a regular GET form, so links are shareable and search works without JavaScript.
  • Dates use YYYY-MM-DD. MAX(review date) is used when reviews exist; otherwise the movie's creation date is used.
  • Keyboard focus, a skip link, form labels and poster alternatives support accessibility.
  • JavaScript only adds delete confirmation and a missing-image fallback. Server permissions are checked independently.

Suggested evaluation tasks: find a named movie; clear an unsuccessful search; locate Add movie after login; cancel deletion; identify the last review date. Student 5 should record actual completion, errors and timings during testing.
